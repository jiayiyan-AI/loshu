# 洛书 (loshu)

一个多维表（multi-dimensional table）应用 —— 表、视图、仪表盘由**单一结构声明** `SchemaDefinition` 驱动：运行时、渲染层、查询层都从它派生，不存在第二份可编辑的结构真相。

## 设计原则

核心思路是**与关系型数据库一一对应**：

> `CREATE TABLE` 里能定义的，就放进 `Table`；不在那里定义的（`JOIN`、聚合），就归视图与仪表盘。

由此定下三层分工：

| 定义 | 声明的是 | 运行时是什么 |
| --- | --- | --- |
| `Table` | 有哪些列、每列什么类型、什么约束 | 可写的记录集合，一行 = 一个业务实体 |
| `View` | 一个查询：取哪张表、怎么筛选排序、附带哪些算出来的列、怎么展示 | 一批行；表列可写，算出来的列只读 |
| `Dashboard` | 一组聚合查询及其绑定的图表 | 统计结果，纯读 |

易用性（如「参与人可多选」）由建表工具层通过映射补上，定义层始终与数据库模型保持一致。
